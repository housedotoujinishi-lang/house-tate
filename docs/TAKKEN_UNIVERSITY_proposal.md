## 1. 目的
ハウステイト社員の **宅建（宅地建物取引士）資格学習** と **実務知識の底上げ** を、
じゃがいOS内で完結させる。営業トレーニング（ロープレ）が「対人スキル」を鍛えるのに対し、
宅建大学は「知識・法令・契約実務」を鍛える **知識レイヤー** として両輪を成す。

## 2. 4本柱（ボス指定）
### ① 問題演習
- 分野別（権利関係／宅建業法／法令上の制限／税・その他）の○×・4択問題
- 出題モード: ランダム／分野別／弱点集中／模試（50問・時間制限）
- 進捗・正答率の可視化、間違えた問題の復習キュー（誤答リスト）

### ② AI解説
- 各問に「なぜ正解か」「ひっかけポイント」「実務での出方」を解説表示
- ※AI接続は現方針で禁止のため、**第1弾は静的な定型解説（事前作成）**。
  AI接続解禁後に動的解説（質問追撃・言い換え）へ拡張。

### ③ 店長分析
- 社員別の正答率・分野別弱点・学習時間・受験準備度をダッシュボード化
- 「誰が・どの分野で・どれだけ詰まっているか」を店長が把握し指導に活用
- クラス平均との比較、伸び率トレンド

### ④ 営業連動
- 宅建知識を**ロープレ／実務KPIに接続**：
  - 例: 売却ロープレ「相続登記未了」→ 権利関係（相続・登記）の該当問題へリンク
  - 例: 「重要事項説明」「媒介契約の種類」→ 営業トレーニングの該当場面に紐付け
- 「実務で出た論点を、その場で問題演習に飛ばす」導線

## 3. 想定画面
1. ホーム（学習進捗・今日の推奨・連続学習日数）
2. 問題演習（出題→回答→即時正誤→解説）
3. 模試モード（50問・採点・分野別スコア）
4. 誤答復習（間違えた問題だけ）
5. 店長分析ダッシュボード（社員別・分野別ヒートマップ）
6. 営業連動リンク集（ロープレ↔分野の対応表）

## 4. データ設計（案）
```
問題: { id, 分野, 難易度, 設問, 選択肢[], 正解, 解説, 実務タグ[], ロープレ連動id[] }
学習ログ: { 社員, 問題id, 正誤, 所要秒, 日時 }   ← 保存方式は要相談（PII方針順守）
```
- 第1弾は問題データを静的JSONで同梱（ロープレと同じ思想）。

## 5. MVP段階案
| 段階 | 内容 | AI/外部 |
|------|------|---------|
| MVP-1 | 分野別問題演習＋静的解説＋自己進捗（メモリ/非PII） | 不要 |
| MVP-2 | 模試＋誤答復習＋店長分析（静的デモ→実集計） | 不要 |
| MVP-3 | AI解説（動的）＋ロープレ実績との相関分析 | 要AI接続（解禁後） |

## 6. 想定効果（概算）
- 受験合格率の底上げ／資格手当・更新要件の充足
- 重説・媒介・税の知識不足による商談事故の低減
- 店長が弱点を定量把握 → OJTの的を絞れる

## 7. 制約・前提（現行方針を踏襲）
- Supabase / SQL / RLS / Auth 変更なし
- 外部API / OpenAI / Claude / Google Sheets 接続なし（MVP-1/2）
- localStorage への本文・個人情報保存なし（学習ログの保存方式は別途相談）
- 既存機能・顧客タブには触れない

## 8. 論点（承認時に決めたいこと）
1. 問題データの出典（自作 / 既存問題集 / 過去問の扱い・著作権）
2. 学習ログの保存可否と方式（非PIIで個人進捗をどう持つか）
3. 営業連動の対応表メンテ責任者
4. ロープレ（packet 2001）とのナビ統合（「人材育成」グループ化の是非）
