# 🎖 昇格試験設計（packet 2008 / DESIGN ONLY）

- 起票日: 2026-06-02 ／ ステータス: **設計docsのみ・未実装**
- 目的: アカデミーの学習・ロープレ・実務スコアを **昇格（キャリアパス）** に接続し、努力を処遇に繋げる。
- 等級: 一般 → 主任 → 店長 → 管理者 → ボス候補。

> ⚠️ docs設計のみ。実装・DB・Auth/権限変更なし。**人事処遇の最終決定は人が行う**（システムは"要件充足の可視化"まで）。

---

## 1. 設計原則
- システムは**昇格"要件の達成度"を可視化**するだけ。**実際の昇格判断・権限付与は店長/ボスが人として実施**（Auth/RLSは変更しない）。
- 3本柱の総合評価：**宅建（知識）×営業（ロープレ実技）×実務（クイズ）**＋ 行動評価（店長所見）。

## 2. 等級別 要件（案）
| 等級 | 宅建 | 営業（ロープレ） | 実務クイズ | その他 |
|------|------|-----------------|-----------|--------|
| 一般 | 基礎演習 正答率60% | 購入ロープレ ランクB以上×3 | 媒介4種テーマ 70% | 入社オリエン修了 |
| 主任 | 模試 合格1回 | 購入＋売却 ランクA×各2／隠し回収70% | 全テーマ 75% | 後輩指導XP一定 |
| 店長 | 模試 合格3回（or 宅建合格） | 売却ロープレ"専任媒介取得"×3／買付到達×3 | 全テーマ 85%・★3突破 | 店長レビュー実施・チーム指標 |
| 管理者 | 宅建合格＋法令上級 | 全シナリオ網羅・地雷回避率90% | 全テーマ 90% | 育成実績（部下の昇格） |
| ボス候補 | — | 経営/育成の総合 | — | 店舗P/L・人材輩出・理念体現 |

> ※閾値は仮置き。実運用前に店長監修で調整。

## 3. 試験フォーマット
- **昇格チャレンジ**：等級ごとに「宅建ミニ模試＋実務クイズ＋指定ロープレ＋店長面談」をパッケージ化。
- **合否判定**：各要件の達成/未達をチェックリスト表示。全充足で「昇格推薦可」フラグ（最終判断は人）。
- **再挑戦**：未達要件だけ再受験。間違いノート/苦手分析（2004）と連動して対策提示。

## 4. 連動
- 宅建大学（2004）：分野別到達度・模試合格回数を要件に直結
- 実務クイズ（2005）：テーマ別正答率を要件に直結
- ロープレ（2001）：ランク・売却ゴール（専任媒介/買付到達）を要件に直結
- 店長モード（2006）：要件への距離を月次表示・面談で所見入力
- ランキング（2007）：昇格バッジ・称号として可視化

## 5. Lv4 設計プロセス
### ① 初期案
宅建合格だけを昇格条件にする。
### ② 自己採点（50点）
知識偏重で「売れる人」を評価できない。実技・実務・育成が抜ける。
### ③ 改善案
宅建×営業×実務×行動の4要素＋等級別の段階要件。
### ④ 最終採用案
**4要素の達成度チェックリスト＋等級別要件＋"推薦可"フラグ（人が最終判断）**。
未達要件は対策（苦手分析/該当ロープレ）へ自動リンク。
### ⑤ 100点に近づける次改善
- **育成実績（部下の昇格・指導XP）を上位等級の必須要件**に（"プレイヤー"から"育てる人"へ）。
- 要件の**重み・閾値をデータで較正**（実際に成果を出す人の特徴を反映）。
- 等級ごとの**ロールモデル事例**を提示し、目標を具体化。

## 6. 効果・負担・優先順位
- **教育効果**：高。学習の"出口"が明確になり、全機能の動機を統合する。
- **売上貢献**：中〜高（中長期）。媒介/買付スキルを昇格要件に組み込み、組織の営業力を底上げ。
- **運用負担**：中。要件の合意形成・面談運用・閾値較正が必要。
- **実装優先順位**：**中〜後段**（Phase3-4）。コア（学習/ロープレ/店長）が回り、データが溜まってから。

## 7. データ設計（案）
```
等級要件: { 等級, 要件id, 種別(宅建/営業/実務/行動), 閾値, 説明, 連動source }
社員達成: { 社員, 要件id, 達成(bool), 現在値, 距離 }
昇格チャレンジ結果: { 社員, 等級, 各要件結果, 推薦可フラグ, 店長所見 }
   ※ 権限(Auth/RLS)は変更しない。可視化のみ。永続保存は非PIIで承認時決定。
```
